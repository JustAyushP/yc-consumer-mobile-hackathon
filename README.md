# yc-consumer-mobile-hackathon

Expo (Expo Router + TypeScript) mobile app backed by Convex. Built for the YC consumer mobile hackathon.

## Getting started

```bash
npm install
cp .env.example .env.local   # then set EXPO_PUBLIC_CONVEX_URL
npm run dev                  # npx convex dev: pushes convex/ to your dev deployment and regenerates convex/_generated
npx expo start               # run the app (Expo Router, routes in src/app/)
```

The Convex dev deployment is `bright-guineapig-371` (`https://bright-guineapig-371.convex.cloud`). `npx convex dev` asks you to log in the first time, or uses `CONVEX_DEPLOY_KEY` when it is set (that is how Capy machines push). `EXPO_PUBLIC_CONVEX_URL` is read in `src/app/_layout.tsx` and inlined into the JS bundle at build time, so it must be set for any build.

The **Messages** tab (`src/app/messages.tsx`) is the end-to-end demo: it lists `messages.list` and writes with `messages.send` from `convex/messages.ts`.

Checks: `npx tsc --noEmit`, `npx expo lint`, `npx expo-doctor`. `expo-env.d.ts` is generated by `npx expo start` and is gitignored; the typecheck needs it. `convex/_generated` is committed so a fresh checkout typechecks; rerun `npx convex dev` (or `npx convex codegen`) after changing `convex/`.

## Cloud builds on Revyl (Capy)

Capy threads build release binaries on Revyl's runners with `tools.mobile.build` (never locally) and install them on cloud phones with `tools.capy.phone`. The release build bundles the JS, so no Metro server is needed. iOS (simulator .app):

```js
await tools.mobile.build({
  action: "start", platform: "ios", app: "yc-consumer-mobile-hackathon",
  source: {
    type: "workspace", path: "yc-consumer-mobile-hackathon",
    commands: [
      "npm ci",
      "CI=1 npx expo prebuild --platform ios --clean",
      "export EXPO_PUBLIC_CONVEX_URL=https://bright-guineapig-371.convex.cloud && WS=$(ls -d ios/*.xcworkspace) && SCHEME=$(basename \"$WS\" .xcworkspace) && xcodebuild -workspace \"$WS\" -scheme \"$SCHEME\" -configuration Release -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' -derivedDataPath ios/build CODE_SIGNING_ALLOWED=NO build | tail -50",
      "mkdir -p build-output && cd ios/build/Build/Products/Release-iphonesimulator && zip -qry ../../../../../build-output/app.zip *.app",
    ],
    output_path: "build-output/app.zip",
  },
});
// then: tools.capy.phone({ action: "attach", platform: "ios" }) and
//       tools.capy.phone({ action: "install", machine, build_id })
```

The full recipe (Android included) lives in the Captain's `revyl-build` skill.
