# Common-character consult demo

`agent.ts` contains an isolated neutral prompt, the `consult_ravo` webhook-tool configuration, and `setLinePrompt({externalRef, consultUrl, lineId})`. The helper reads server-only `KEIKI_API_KEY` and upserts by external reference without connecting any channels. It accepts no private prompt and refuses the existing `ravo-common` standalone character. It is not invoked automatically; this change does not create a live second agent.

The demo uses the **legacy webhook-tool** contract documented in [Keiki's billing example, section 2](https://onkeiki.com/docs/billing-agent-example): `X-Orchid-Api-Key`, `X-Orchid-Trace-Id`, and `{input, context: {phone, channel}}`. `context.phone` is the platform's conversation identity, not a model argument. The server pins the demo agent and explicit logical line `1`; known bindings must match agent, channel, conversation, sender, and line. For this narrow adapter, both conversation and sender are the documented `context.phone` value. Do not use it for group chats or a transport where that value does not uniquely identify a private sender conversation.

This is **not** the signed identity-webhook or Ed25519 external-harness protocol. Signed tool mode omits the legacy key header; it is not silently accepted here. `/keiki/turn` remains disabled. Before a live legacy-tool test, use a deployment key exclusive to this demo agent (not reused for other agents) and inspect an isolated tool payload: the newer [conversation-auth docs](https://onkeiki.com/docs/conversation-auth) promise richer signed context but do not publish its complete wire shape. The legacy envelope has no documented agent-id field, so the configured agent is a fixed single-agent assumption, not an independently verified payload field. Never copy model-provided identity IDs into bindings.

The ingress starts disabled. Set server-only `KEIKI_TOOL_API_KEY` to the isolated deployment's key, `KEIKI_DEMO_AGENT_ID` to its agent id, `KEIKI_DEMO_LINE_ID=1`, and explicitly `KEIKI_DEMO_INGRESS_ENABLED=true` only after verifying that key's exclusive use and tool context. Pre-provision `keikiBindings` with the full transport tuple and known player/group, `active=true`; for this adapter `senderId` and `conversationId` both equal `context.phone`. This slice does not implement joining or bind a sender by phone lookup. The tool URL includes `?lineId=1` and must agree with the server's pinned line. Completed traces return 409 without their stored directive until Brain publishes a read-only current-entitlement check; binding checks alone cannot authorize stale guidance. No completed, pending, or uncertain trace automatically re-consults.

Trace-based dedupe suppresses repeats of a known tool call, not every redelivery of a provider message under a different trace. The model supplies `playerMessage`; without a verified provider transcript this is not proof of verbatim transport text. No exactly-once game-effect guarantee is claimed. Pending or uncertain receipts require manual investigation, not automatic retries.

Offline tests use fake transport and master responses; they do not prove Keiki model execution, delivery, or gameplay correctness. Free onboarding Live Test disables tools and cannot run this loop. The API gateway is a separate channel, and is not required for an inbound messaging tool; an actual tool-capable messaging plan still needs verification. No line, subscription, channel, or real-person message is created by this repository change.
